E-portfolio Reflection (Project 3)

Three-stage model: What? So What? Now What?

Name: Shayan Siddiqui  •  MacID: Siddm47

"Early testing turned our design assumptions into evidence we could trust."

🔎 What?

During Project 3 in our design studio, my biggest "wait, we need to rethink this" moment happened when we first tested our Arduino prototype with the ultrasonic sensor and DC motor and it kept triggering at the wrong time. I expected the sensor to read one clear distance and the motor to run once, but in real testing the distance value jumped around, so the motor would start, stop, or activate twice, even when nothing changed. We were trying to test feasibility, meaning whether the idea could work reliably in real use, and this test showed our first logic was not reliable. The turning point was when we watched the serial monitor numbers flicker and heard the motor buzz on and off, and it made it obvious that our design needed an "armed" reset rule and a better trigger threshold. We changed our code so it only triggers when the distance crosses a set point, then locks until the hand moves away, and that made the system predictable instead of random. That moment challenged my assumption that a design that works "on paper" will work the same in real life, and it pushed us to make decisions based on test results instead of what we hoped would happen.

🧠 So What?

This incident taught me that early testing is very important because it quickly shows problems you cannot see from a sketch or code plan. I realized I had a misconception that if the logic is correct, the device will behave consistently, but real sensor data is messy and you have to design around the noise. It also improved how I make decisions, because instead of picking changes based on what "sounds right," we used the test results to choose thresholds and add an armed reset rule. If we had delayed testing, we would have spent more time building around a design that was not reliable, and the fix would have been harder later.

🚀 Now What?

I learned that testing needs to happen early and be built into the plan, because real-world data will expose issues that you cannot predict from just designing on paper. This matters because as an engineer I need to make decisions based on evidence, not assumptions, especially when reliability affects safety and performance. Next time, I will test a simple version of the idea as soon as possible, collect clear data (like repeated trials and recorded measurements), and only then lock in design choices like thresholds, materials, or mechanisms.
